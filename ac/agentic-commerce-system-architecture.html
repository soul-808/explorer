03

Primary flow, human not present purchase

The hardest case, because no human is at the keyboard when money moves. Human present flows are a strict subset with step 06 replaced by a live approval.

  1. EXT-01 to EDG-01, IF-01Cardholder enrolls an agent. Authenticates in the bank app, selects an agent, sets caps, merchant categories and an expiry. Step up authentication is required above the product policy threshold.
  2. APP-01 to EXT-03Bank requests an Agentic Token. Enablement service calls Mastercard to mint a token bound to the agent identifier, merchant scope and consent policy. The primary account number never leaves the CDE.
  3. APP-11 to DAT-02, IF-13Consent is written to the ledger. Append only, with the consent receipt identifier that will appear on every downstream artifact.
  4. EXT-01 to EXT-02Cardholder states an intent. The agent captures the goal and constraints and produces a signed intent mandate. The bank sees the mandate, not the conversation.
  5. EXT-02 to EDG-02, IF-02Agent presents itself. Request headers are signed under RFC 9421. The gateway verifies against the network operated key directory before any business logic runs.
  6. EXT-02 internalConditions are met and the cart locks. The agent generates a cart mandate carrying exact items, price, merchant and timestamp, signed under the earlier intent mandate.
  7. EXT-05 to EXT-04 to EDG-04, IF-04Authorization arrives. The message carries the agent indicator, token assurance level and the mandate reference.
  8. EDG-04 to APP-04 to APP-03, IF-08, IF-09Decision inside the latency budget. Fraud scores with agent aware features. Limits validates the cap, velocity and merchant scope against the mandate. Any mismatch declines with a distinct reason code.
  9. APP-08 to EXT-01Cardholder is told. Push notification within seconds, showing what the agent bought and offering one tap to dispute.
  10. APP-06 to DAT-05, IF-15Evidence is sealed. Mandate chain, agent identity, action log, approved cart and delivery proof are written once and retained. This is what makes the claim defensible later.
  11. APP-07 to EXT-03, IF-14If disputed, the pack is already built. Regulation Z timers run from claim intake. Evidence assembly is a lookup, not an investigation.
04

Architecture decisions

Recorded here so the drawing can be read without the meeting that produced it.

AD-01 Mandate vault is a new system of record

  • A signed artifact authorizing a future purchase has no existing home in the estate.
  • Rejected: storing mandates as blobs on the consent record. Retrieval and retention obligations differ.
  • Consequence: a new HSM backed store with its own retention, dual control and examination posture.

AD-02 Agent traffic terminates in its own gateway

  • Signature verification, rate limiting and agent reputation are unlike consumer app traffic.
  • Rejected: extending the existing open banking gateway. Different auth model, different blast radius.
  • Consequence: EDG-02 is separately deployable and separately disableable.

AD-03 Decisioning stays in the authorization path

  • Scope enforcement after the fact is a reconciliation exercise, not a control.
  • Rejected: asynchronous post auth validation with reversal. Poor customer outcome, weak examination story.
  • Consequence: an 80 ms budget for APP-04 and 25 ms for APP-03, which constrains model complexity.

AD-04 Offer eligibility is a service, not a report

  • An agent needs cart level card value before checkout, not statement level value after.
  • Rejected: exposing the existing rewards batch. Wrong latency, wrong granularity, wrong consumer.
  • Consequence: APP-05 fronts DAT-04 with a read through cache and a public facing contract.

AD-05 Evidence is captured on every agent order

  • Backfilling evidence after the first dispute wave is not possible.
  • Rejected: capture on dispute only. The artifacts are ephemeral at the agent surface.
  • Consequence: storage and retention cost from day one for transactions that will mostly never be disputed.

AD-06 Network agnostic internal model

  • Mastercard Agent Pay is the launch partner, not the internal data model.
  • Rejected: modelling on Agentic Token semantics directly. Locks the estate to one network.
  • Consequence: an internal mandate and scope model with adapters per network. Slower to launch, cheaper to extend.
05

Cross cutting concerns and non functional requirements

Security

  • Zero trust service mesh, mutual TLS between all internal containers, SPIFFE workload identity.
  • Prompt injection is treated as an external threat with no internal mitigation. Controls are deterministic: caps, allow lists, mandate binding.
  • Agent credentials are scoped, short lived and revocable in real time from the bank app.
  • Key material in HSM. Dual control on mandate vault access. Privileged access reviewed quarterly.

Availability and performance

  • Authorization path 99.99 percent, active active across two regions.
  • Agent gateway 99.9 percent. Degradation declines new agent orders rather than failing open.
  • Offer eligibility 99.5 percent. Timeout returns no offer rather than blocking checkout.
  • Global kill switch at product and agent level, effective within 60 seconds.

Data and retention

  • Mandates retained for the statute of limitations on the underlying claim, minimum seven years.
  • Audit archive write once, examination ready, indexed by consent receipt.
  • No conversation content ingested. The bank stores mandates and outcomes, not the prompt.
  • Right to delete constrained by record keeping obligations. Documented in the privacy assessment.

Observability

  • Distributed tracing from agent request through authorization, correlated on consent receipt.
  • Decline reason codes distinguish scope breach, cap breach, expired mandate and fraud.
  • Unmandated spend on an agent enabled account is a page, not a ticket.

07

Scope, assumptions and open decisions

In scope, release one

  • Credit card products only, human present agent purchases.
  • Mastercard Agent Pay as the sole network integration.
  • Enrollment, consent, limits, evidence capture and alerting.

Out of scope

  • Debit and deposit funding sources.
  • Human not present execution, gated behind AD-03 latency proving and a written network dispute rule.
  • Commercial and small business cards.
  • Third party agent access to offer eligibility.

Assumptions

  • Mastercard continues to operate the agent key directory and registry.
  • Card core can carry an agent indicator without a release train dependency beyond one quarter.
  • Merchant side agent verification adoption continues to spread at the edge.

Open decisions

  • Whether the bank writes a voluntary liability commitment for registered agent errors ahead of network rules.
  • Mandate retention period, pending legal opinion.
  • Whether offer eligibility is exposed to agents directly or only through the network.
  • Dual protocol support for a second network, and on what trigger.
